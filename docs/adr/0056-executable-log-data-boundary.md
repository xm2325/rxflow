# ADR 0056 — Executable request/log data boundary

## Context

A source-code rule such as “do not log request bodies” can silently regress. Healthcare integration code benefits from an executable check that sends values which would be sensitive in a real system and verifies that operational output remains data-minimised.

## Decision

The release pipeline now runs a spawned-server request-boundary gate. It sends synthetic patient, clinical-note, and unsafe correlation sentinels through failure paths, captures stdout/stderr, and fails if any sentinel appears. The same gate verifies that a valid opaque correlation identifier is retained so safety does not remove useful tracing.

## Evidence

`npm run test:http:request-boundary` starts the compiled API with a fresh SQLite database and checks media-type enforcement, idempotency metadata, correlation replacement, FHIR JSON support, an idempotency conflict, malformed JSON, and process-log contents.

## Boundary

This is a regression test over the local process output generated by the covered paths. It is not a claim about an external cloud logging pipeline, log retention policy, redaction service, or regulatory compliance.
